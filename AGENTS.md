# Repository Guidelines

## Project Structure and Module Organization

This directory currently contains only this guide. Keep the first contribution easy to navigate. Once the project has a language and framework, follow their standard layout for source code, tests, and assets. Add a root README with the main entry point, the purpose of each top-level directory, and the prerequisites for local development.

## Build, Test, and Development Commands

No build, development, or test commands are configured yet. When adding the first runnable code, document the exact commands to install dependencies, start the project locally, and run its checks. Include the build command if the project has a build step. Verify the documented commands from a clean checkout and record any required runtime versions or environment variables.

## Coding Style and Naming Conventions

Use the chosen language and framework conventions for indentation, filenames, and identifiers. Match nearby code as conventions emerge. If the project adopts a formatter or linter, check in its configuration and document how to run it. Use descriptive names and keep unrelated formatting changes out of feature and fix commits.

## Testing Guidelines

No test framework or coverage threshold is configured yet. When adding tests, follow the framework's discovery conventions and name cases after the behavior they verify. Cover the main behavior and relevant failure cases. Document how to run the full suite and a single test file once those commands exist.

## Commit and Pull Request Guidelines

There is no Git history in this directory to establish a commit convention. Use short, imperative subjects such as “Document local setup.” In pull requests, explain what changed and why, list the checks you ran, and link any related issue. For visible interface changes, include screenshots that show the affected views.
